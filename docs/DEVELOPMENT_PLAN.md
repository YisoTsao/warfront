## 3. 各階段完成內容與驗證

### Phase 2 — Blender 資產流程

- `packages/map-schema`：manifest、碰撞資料（zod 驗證）、Blender 命名慣例（`ENV_*`、`COLLISION_*`、`GAMEPLAY_*`、`LIGHTING_Reference`、`_LOD0/_LOD1`）。
- `tools/map-build`：視覺依 64 m 分塊（地形分塊永遠載入、細節分塊依距離串流）、相同網格自動合併為 `EXT_mesh_gpu_instancing`、LOD 群組、Meshopt 壓縮；碰撞輸出為方塊、三角網格或高度場（可指定只擋移動或只擋子彈）；出生點、據點、禁區、水域、光照從 empty 與自訂屬性讀出；共用網格庫（`library.glb`）與共用貼圖（`textures/`）。
- 森林谷地轉換器（`tools/map-build/src/forest`）：把 blender-mcp-asset-generator 的 phase1–5 輸出（高度圖、水體、植被與岩石實例清單、建築、配置）組成符合匯入慣例的 GLB，見 `ASSET_PIPELINE.md` §5。執行期資料：分塊 6.2 MB、網格庫 1.4 MB、貼圖 1.7 MB、碰撞 2.3 MB（JSON，主要是 513 × 513 高度場）。
- 範例谷地產生器：依 Blender 匯出慣例產生測試 GLB（256 m 地形、河流、石橋、可進入的房屋、哨站、約 480 棵樹）。原始 2.2 MB → 執行期 0.55 MB（20 個分塊）+ 碰撞 0.79 MB（gzip 0.22 MB）。
- 前端：GLTFLoader + MeshoptDecoder + KTX2Loader、依距離串流與卸載、LOD 切換、陰影跟隨玩家。
- 驗證：map-build 單元測試 6 個；e2e 5 個（載入、instancing、房屋牆壁與門、只擋人的鐵絲網、分塊串流、地形行走）。

### Phase 3 — 武器與單機戰鬥

- 7 把武器（數值沿用舊版 UE5）、5 種配件、射擊模式、換彈與逐發裝填、散佈與 bloom、後座力與回復、ADS、切槍。
- 武器狀態機與彈道（種子規則）放在 `packages/simulation`，與伺服器共用。
- 程序產生的第一人稱武器模型（另一個渲染 pass，不穿牆）、物件池特效、WebAudio 合成空間音效、AnimationMixer 驅動的士兵模型、靶場假人。
- 驗證：e2e 7 個（命中與 hit marker、射速與換彈、擊殺與復活、切槍與射擊模式、霰彈槍、音效、主選單）。

### Phase 4–8 — 多人、戰鬥、團隊死鬥、兵種、征服

- 伺服器：`Match`（純邏輯，可單元測試）+ Colyseus `MatchRoom`；30 Hz 固定 tick、15 Hz 快照。
- 輸入即開火請求：伺服器以相同武器狀態機產生射擊；伺服器 hitbox、地圖遮擋、延遲補償（最多 0.25 秒）、友傷規則。
- 血量（倒地、救援、流血、放棄）、擊殺與助攻、計分、手榴彈、四個兵種技能、禁區與地圖邊界。
- 模式：團隊死鬥（分數上限、時間上限）、征服（佔領、爭奪、票數、流失、出生點選擇）；暖身 → 進行 → 結算 → 自動下一場。
- 用戶端：預測與修正、遠端插值、延遲量測、斷線自動重連（SDK 重連，失敗時以同一訪客身分重新加入並取回位置）、部署畫面、伺服器列表、戰術地圖與小地圖、計分板、結算畫面。
- 驗證：伺服器單元測試 25 個；e2e 7 個（雙瀏覽器垂直切片、重連、配裝、征服、伺服器列表、16 人滿房、完整對戰流程）。

### Phase 9 — AI 與營運

- bot：與真人相同的輸入與規則；找目標、反應延遲、瞄準誤差收斂、左右移動、佔點、醫療兵救援、卡住時繞路。
- 觀測：`/metrics`（JSON 與 Prometheus）——tick 時間與漂移、快照大小、收發量、延遲、拒絕與可疑輸入、房間與連線、對戰完成數、房間錯誤、客戶端錯誤；結構化 JSON 日誌；`/client-errors` 接收瀏覽器未處理例外。
- 畫質：低／中／高預設、渲染解析度、動態解析度、陰影、植被（串流距離與特效數量）、暈影後處理；按鍵重新綁定、音量。
- 部署：伺服器 Dockerfile（打包成單一 `index.js`，已在空目錄以 Node 獨立執行驗證）、CI workflow、環境變數範例。

### Phase 10 — 最佳化與上線

已完成：16 人負載測試（`PERFORMANCE.md`）、安全檢視（`SECURITY_REVIEW.md`）、延遲與斷線情境測試、畫質等級。尚未完成的項目見 §5。

## 5. 已知限制與尚未完成

1. **森林谷地的草地與小物件尚未匯入**：草與花（約 22 萬個實例）需要 GPU 端的草地系統；樹樁與枝堆在 Blender 端沒有匯出網格。Blackwood Valley 的原始檔仍未提供。
2. **參考 PC 效能尚未量測**：60 FPS 目標需要在指定的參考 PC 上量測（主規格 §3.3）。
3. **Firefox 未測試**：測試環境只有 Chromium。
4. **WebGPU 尚未評估**：維持 WebGL 2 基準路徑；渲染器與材質已模組化，之後可以評估。
5. **美術、動畫、音效為暫代品**：武器與士兵是程序產生的幾何，動畫是程式建立的關鍵影格（仍由 AnimationMixer 播放），音效是 WebAudio 合成。介面已預留載入 glTF 與音檔的欄位。
6. **實際部署尚未進行**：平台未定；Dockerfile 與 CI 尚未在真正的平台上執行（本環境沒有 Docker）。
7. **傳輸只有 WebSocket**：已透過 `GameTransport` 介面隔離；WebTransport 需在量測後評估（主規格 §2.4）。
8. **告警**：只提供 Prometheus 指標與範例告警規則，尚未接上告警系統。
9. **角色之間不互相碰撞**：避免各端預測不一致的取捨（見 `NETWORKING_SPEC.md`）。

## 6. 下一步建議

4. 美術資產（武器、角色、動畫、音效）取代暫代品。
5. 帳號系統（Supabase Auth）與對戰紀錄寫入資料庫。
