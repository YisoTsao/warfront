# 效能量測

> 依據：`FRONTLINE_WEB_PROJECT_SPEC.md` §3.3、§15。量測日期：2026-11-03。
> **重要**：雲端開發環境沒有 GPU，瀏覽器以 SwiftShader 軟體繪圖，畫格率不能代表玩家電腦。前端的 60 FPS 目標必須在參考 PC 上量測。

## 1. 伺服器

### 1.1 16 個真實客戶端（`bun run load-test`）

16 個 Colyseus 客戶端（不是 bot）加入同一場灰盒地圖，每個 tick 送出隨機移動、衝刺、跳躍與開火的輸入，持續 60 秒。

| 項目 | 結果 |
|---|---|
| 伺服器 tick | 平均 1.37 ms、p95 2.48 ms、最大 7.55 ms（預算 33.3 ms） |
| tick 漂移 | 平均 0.16 ms、p95 0.73 ms |
| 快照 | 每位客戶端 15.0 次／秒；平均約 1.25 KB（JSON 估算，實際 msgpack 較小） |
| 下行頻寬 | 每位客戶端約 18 KB/s（JSON 估算） |
| 被拒絕的輸入 | 0 |
| 程序記憶體 | RSS 216 MB、heap 46 MB |

在範例谷地（地形三角網格碰撞）以打包後的 `index.js` 執行 8 人負載測試：tick 平均 2 ms、p95 3.3 ms。

森林谷地（513 × 513 高度場 + 3,295 個碰撞方塊）征服模式、16 個 bot、90 秒模擬：tick 平均 3.05 ms、最大 35.7 ms（`forest.test.ts`）。

### 1.2 瀏覽器 + 15 個 bot（e2e）

1 個瀏覽器玩家 + 15 個 bot 在灰盒地圖對戰 20 秒：tick p95 低於 33 ms（e2e 驗證）。bot 會在 1 分鐘內交火並造成擊殺。

## 2. 前端

### 2.1 已實作的效能機制

| 機制 | 說明 |
|---|---|
| 分塊串流 | 依距離載入與卸載細節分塊，卸載時釋放 GPU 資源 |
| GPU instancing | 地圖中重複的網格（樹、灌木、岩石）由 map-build 合併 |
| LOD | 依距離切換 LOD0 / LOD1 |
| Meshopt 幾何壓縮 | 範例谷地執行期資料 0.55 MB |
| 共用網格庫與貼圖 | 森林谷地原本每個分塊各帶一份樹木與岩石網格（共 23 MB），改成網格庫後分塊 6.2 MB + 網格庫 1.4 MB + 貼圖 1.7 MB；GPU 上也只有一份 |
| 逐實例 LOD | 每個樹木／岩石實例依自己的距離分到 LOD0 或 LOD1（玩家移動 1.5 m 才重算）；蕨類 70 m、小石頭 60 m、灌木 150 m 外不畫 |
| 畫質預設 | 低／中／高：渲染解析度、陰影貼圖大小、植被（串流距離、特效數量）、後處理 |
| 動態解析度 | 畫格時間持續超過 20 ms 時降低渲染解析度（最低 60%），低於 13 ms 時恢復 |
| 陰影跟隨 | 太陽陰影只涵蓋玩家附近，並以像素對齊避免閃爍 |
| 物件池 | 特效粒子、曳光彈預先建立，戰鬥中不建立 GPU 資源 |
| React 隔離 | 每畫格的資料不經過 React（e2e 驗證） |
| 延後載入 | 選單外殼 268 KB（gzip 84 KB）；遊戲本體進入遊戲時才下載 |

### 2.2 開發環境量測（僅供參考）

| 場景 | 結果（SwiftShader，1280×720） |
|---|---|
| 灰盒地圖 | 約 5 FPS，draw calls 8–70 |
| 範例谷地 + 10 個 bot | 約 4 FPS |
| 森林谷地（約 5,800 個實例、可見約 3,200 個） | 約 4 FPS；載入（含網格庫與 32 個分塊）約 13–40 秒 |

### 2.3 參考 PC 量測（待進行）

依主規格 §15.4 記錄：裝置、瀏覽器、解析度、畫質、地圖位置、FPS 百分位、網路條件。建議場景：

1. 空地圖基準（灰盒）。
2. 森林谷地全景（南方 HQ 往北、橋梁、伐木場的密林）。
3. 16 名角色同時在畫面中、同時移動與開火（`?match=tdm&bots=16`）。
4. 高密度植被區。
5. 村落室內。
6. 網路延遲與丟包（Chrome DevTools 網路節流，或伺服器的 `COLYSEUS_LATENCY` 環境變數）。
7. 分頁切到背景後回來、斷線重連。
