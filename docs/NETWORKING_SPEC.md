# 網路規格

> 依據：`FRONTLINE_WEB_PROJECT_SPEC.md` §2.4、§6.1、§10。本文件描述**已實作**的行為；數值為起始參數，要以實際網路測試調整。

## 1. 原則

- 一個 Colyseus 房間 = 一場對戰，上限 16 人、每隊 8 人；人數不足時以 bot 補位（bot 走同一套權威規則）。
- 伺服器擁有所有最終結果：位置、血量、彈藥、射速、命中、擊殺、分數、據點。
- 客戶端只送輸入，不送位置、命中目標或傷害值。
- Colyseus 只負責房間、配對、訊息與重連；移動權威、武器規則、命中驗證、延遲補償、模式規則都在 `apps/game-server/src/game`。
- 高頻戰鬥同步不使用 Supabase Realtime、資料庫或 serverless function。

## 2. 傳輸

- 目前使用 Colyseus WebSocket（正式環境為 WSS）。訊息由 Colyseus 以 msgpack 編碼。
- 遊戲只透過 `GameTransport` 介面（`apps/web/src/game/network/GameTransport.ts`）送收訊息；之後若以 WebTransport 傳送移動快照，只需要新增實作。
- 伺服器 WebSocket 單一訊息上限 16 KB。

## 3. 頻率

| 項目 | 值 |
|---|---|
| 伺服器固定 tick | 30 Hz（`TICK_RATE`） |
| 客戶端模擬（預測） | 30 Hz，與伺服器相同；渲染以內插維持平順 |
| 快照 | 15 Hz（每 2 個 tick） |
| 對戰狀態（分數、據點、計分板） | 2 Hz |
| 遠端插值延遲 | 0.12 秒（約 2 個快照） |
| 延遲補償上限 | 0.25 秒 |

## 4. 訊息

訊息型別定義在 `packages/shared/src/net/protocol.ts`，伺服器以 zod 驗證所有客戶端訊息（`apps/game-server/src/room/schemas.ts`）。

| 方向 | 型別 | 內容 |
|---|---|---|
| C → S | `in` | 輸入框（1–4 個）：序號、前後與左右軸、按鈕位元、想要的姿勢、yaw、pitch、想要的武器欄、畫面上的伺服器 tick（`vt`） |
| C → S | `loadout` | 兵種、主副武器、配件（下次部署生效；伺服器會修正不合法的選項） |
| C → S | `team` | 換隊（人數差不能超過 1，bot 可以讓位） |
| C → S | `deploy` | 出生點（基地或己方據點） |
| C → S | `ping` | 時間戳記與上一次的 RTT |
| C → S | `dbg` | 開發指令（只有 `DEV_COMMANDS=1` 時有效） |
| S → C | `welcome` | 玩家編號、隊伍、對戰種子、地圖、模式 |
| S → C | `snap` | tick、最後處理的輸入序號（ack）、自己的完整狀態、其他玩家（緊湊陣列）、手榴彈 |
| S → C | `ev` | 開火特效、命中確認、受傷方向、擊殺、爆炸、救援、技能、佔領、訊息 |
| S → C | `match` | 階段、剩餘時間、分數或票數、據點、計分板、勝方 |

按鈕位元：衝刺、跳躍、瞄準、開火、換彈、射擊模式、手榴彈、技能、互動、放棄。跳躍、換彈、射擊模式、手榴彈、技能是「按下那一刻」的邊緣事件。

## 5. 輸入處理（伺服器）

- 每個輸入框**只處理一次、依序處理**；序號重複或過舊的直接丟棄。
- 每位玩家每 tick 補 1 個處理額度，最多累積 8 個：網路抖動造成的成批輸入會在下一個 tick 補處理；送得比 30 Hz 快的客戶端不會被處理得更快（防加速），佇列溢出會計為可疑。
- 超過 0.5 秒沒有輸入（例如分頁被隱藏）才以閒置輸入推進（重力等）。
- 數值範圍：軸向夾在 -1–1、pitch 夾在 ±89°、姿勢與武器欄位限制在合法值；含 NaN 的輸入框丟棄。

## 6. 開火與命中（伺服器）

開火不是獨立的請求，而是輸入框中的扳機按鈕。伺服器以與客戶端相同的武器狀態機推進，產生射擊。逐項對照主規格 §6.1：

| 主規格要求 | 實作 |
|---|---|
| 玩家屬於這場對戰 | 只處理已加入房間的玩家的輸入 |
| 存活且可以開火 | 只有存活玩家會推進武器；倒地與死亡不能開火 |
| 武器已裝備且有彈藥 | 伺服器的武器狀態機（含舉槍時間、換彈狀態） |
| 射速與射擊模式合法 | 同上，以伺服器時間軸計算；客戶端無法加快 |
| 換彈狀態允許開火 | 同上 |
| 射擊序號合法不重複 | 序號由伺服器的武器狀態機產生；輸入序號不能重複 |
| 視角在合理範圍 | 使用輸入框的 yaw / pitch（伺服器接受的視角狀態），pitch 夾在 ±89° |
| 射擊原點在伺服器已知位置 | 原點 = 伺服器角色位置 + 姿勢眼高，不採用客戶端座標 |
| 射線打到有效目標、沒有被地圖擋住 | 先對地圖碰撞（擋子彈層）打射線，再對其他玩家的 hitbox 判定，取最近者 |
| 不信任客戶端送來的目標 | 客戶端不送目標；命中由伺服器判定 |

**散佈種子**：`hashSeed(對戰種子, 玩家編號, 武器欄位, 射擊序號)`，兩端算得出同一個值但客戶端無法挑選（舊版 UE5 讓客戶端自選種子，已修正）。

**延遲補償**：伺服器保存最近 0.25 秒每位玩家的 hitbox 姿勢。開火時依輸入框的 `vt`（客戶端畫面上遠端玩家所在的 tick）回溯；超過上限就使用最舊可回溯的紀錄；本 tick 的姿勢要到 tick 結束才記錄，所以請求目前 tick 時使用上一個 tick。

**友傷**：模式設定 `friendlyFire`（預設關閉）。

## 7. 客戶端預測與修正

- 本機玩家立即套用輸入，並保存每個輸入框與預測結果（位置、速度、預期速度、著地、姿勢、彈藥）。
- 收到快照時：
  - ack 沒有前進 → 沒有新資訊，不比對。
  - 取出 ack 對應的預測，與伺服器狀態比較；誤差超過 3 cm 或姿勢不同 → 回到伺服器狀態，重播尚未確認的輸入框。
  - 彈藥與射擊序號依「伺服器在 ack 的值 − 本機在 ack 的預測」修正差值。
- 渲染位置保留前一個畫面的位置並內插，修正時不會瞬間跳動。
- 結果：一般移動（走、跑、跳）不需要修正（e2e 驗證）。

## 8. 遠端玩家

- 以伺服器 tick 為時間軸緩衝快照，畫面顯示在「估計的伺服器 tick − 0.12 秒」。
- 新快照晚到時最多外插 3 個 tick；過舊或亂序的快照忽略；重生時（位置跳超過 8 m）不內插。
- 角色之間**不互相碰撞**：避免各端預測不一致的取捨。

## 9. 斷線與重連

- 伺服器：非主動離線時保留位置 30 秒（`RECONNECT_SECONDS`），角色移出模擬；保留期內以同一訪客身分加入可以取回原本的玩家編號、隊伍與分數。
- 客戶端：先由 Colyseus SDK 自動重連；SDK 無法恢復時，以同一訪客身分重新加入同一個房間（最多 30 秒，指數退避）。
- 同一個訪客身分已在房間中且連線中 → 拒絕重複加入（409）。
- 重連後角色需要重新部署，避免斷線期間的狀態不一致。

## 10. 防作弊基準

見 `SECURITY_REVIEW.md`。摘要：伺服器權威（血量、彈藥、射速、命中、擊殺、分數、據點）、移動由伺服器模擬、輸入速率與數值範圍驗證、訊息結構驗證、訊息與加入限流、可疑行為計數與日誌。客戶端混淆不能取代伺服器權威，也不宣稱能防止所有作弊。

## 11. 量測

`/metrics` 提供：房間 tick 時間與漂移、快照大小、收發訊息與位元組、RTT、被拒絕的輸入、被限流的訊息、可疑輸入、房間與連線數、斷線與重連數、對戰完成數、房間錯誤、客戶端錯誤、程序記憶體與 CPU。量測結果見 `PERFORMANCE.md`。
