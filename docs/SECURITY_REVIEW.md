# 權威規則與安全檢視

> 依據：`FRONTLINE_WEB_PROJECT_SPEC.md` §6.1、§10.6、§14。檢視日期：2026-11-03。
> 結論：MVP 的權威模型符合主規格；以下列出每一項的做法、測試與剩餘風險。**不宣稱能防止所有作弊。**

## 1. 伺服器權威

| 項目 | 做法 | 測試 |
|---|---|---|
| 位置 | 伺服器以輸入模擬移動；客戶端不送位置 | `match.test.ts`「只能經由輸入移動」 |
| 速度 | 伺服器的角色控制器套用速度上限 | 同上（1 秒移動 ≤ 衝刺速度） |
| 輸入速率（防加速） | 每 tick 補 1 個處理額度，上限 8 | 「送得比 30 Hz 快的客戶端不會被處理得更快」 |
| 射速、彈藥、換彈 | 伺服器的武器狀態機 | 「射速由伺服器限制」 |
| 散佈 | 伺服器重算；種子由伺服器規則推算，客戶端不能挑選 | `simulation.test.ts`「同一個種子得到相同的彈丸方向」 |
| 命中 | 伺服器 hitbox + 地圖遮擋 + 有上限的延遲補償 | 「瞄準敵人開火會造成傷害；打偏不會」、延遲補償測試 |
| 傷害、擊殺、分數、據點 | 只在伺服器計算 | 擊殺、征服、完整對戰流程測試 |
| 友傷 | 模式設定，預設關閉 | 「友傷預設關閉」 |
| 對戰結果 | 對戰結束時由伺服器回報 | 「達到分數上限時結束對戰並回報結果」 |

## 2. 輸入與訊息驗證

- 所有客戶端訊息以 zod 驗證結構；不合法的訊息丟棄並計數（`rejectedInputs`）。
- 輸入框：序號必須遞增；數值範圍夾住；NaN 丟棄。
- 單一 WebSocket 訊息上限 16 KB。
- 限流：輸入 100 則／秒（突發 120），其他訊息 10 則／秒；10 秒內被丟棄超過 300 則就中斷連線。
- 加入：每個 IP 每 10 秒 12 次（`JOIN_RATE_LIMIT`）；加入參數格式驗證；名稱過濾 `<` `>` 並限制長度。
- 同一個訪客身分不能重複加入同一場（409）。
- 來源限制：設定 `ALLOWED_ORIGINS` 後，只接受指定網站的連線。
- `/client-errors`：每個 IP 每分鐘 20 次，只記錄截斷後的字串。

## 3. 開發指令

`dbg` 訊息（傳送玩家、略過暖身）只有在伺服器設定 `DEV_COMMANDS=1` 時才會執行。正式環境必須關閉；`.env.example` 與 `DEPLOYMENT.md` 已註明。

## 4. 剩餘風險

| 風險 | 說明 | 建議 |
|---|---|---|
| 自動瞄準、透視 | 客戶端知道所有玩家位置（快照包含全部玩家） | 之後加入依視線的興趣管理（只送看得到或聽得到的敵人）、瞄準行為統計 |
| 延遲補償濫用 | 客戶端可以把 `vt` 設在 0.25 秒前 | 已有上限；可以再依量測到的 RTT 限制回溯量 |
| 訪客身分可偽造 | 沒有帳號系統，guestId 存在瀏覽器 | 帳號系統上線後改用驗證過的身分 |
| 分散式攻擊 | 限流以單一程序、單一 IP 計算 | 部署時在前端加上平台的 DDoS 防護 |
| 視角瞬間轉動 | 無法區分快速甩槍與作弊 | 記錄異常的轉速與命中率供人工檢查 |

## 5. 可疑行為紀錄

- 佇列溢出（持續送太快）→ 玩家的 `suspicious` 計數與 `/metrics` 的 `suspicious`。
- 被拒絕與被限流的訊息 → `/metrics`。
- 因限流中斷連線 → `client_rate_limit_disconnect` 日誌。
